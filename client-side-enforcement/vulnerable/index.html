Lab: Client-Side Enforcement of Server-Side Security

What it is

Client-Side Enforcement happens when a website relies on the browser to control user permissions instead of the server. An attacker can modify client-side data to bypass these restrictions. The solution is to enforce all important permissions on the server side.

4. Why It Matters

Any check or restriction implemented solely on the client side (such as hiding buttons, disabling UI elements, or storing user roles in JavaScript variables or localStorage) is completely under the attacker's control. Users can easily open browser DevTools, modify variables/storage, or send direct HTTP requests to bypass UI restrictions and perform unauthorized actions (such as deleting resources or accessing restricted features).

Explain the Damage: Because the check happens inside the browser, an attacker can easily bypass it using DevTools or by changing variables/storage, allowing regular users to perform admin actions like deleting products or accessing restricted features.

Real Incident: Security researchers (such as Synack Red Team) have documented web applications that verified two-factor authentication (2FA) or user permissions solely in front-end code. By intercepting and modifying a simple response value in the browser, attackers bypassed the security check entirely and gained unauthorized access to restricted features. (A classic documented example of client-side check bypass is CVE-2006-6994).

5. The Fix

The Fix: Never trust the browser. Always check the user's real role and permissions on the server before allowing sensitive actions like deleting data
